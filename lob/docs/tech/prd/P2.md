# P2 — matching engine (price-time priority)

Goal: an in-process **limit order book + matching engine**. Submit limit/market orders and
cancels/replaces; it maintains a book and emits executions. Single symbol. See ADR-0002 for
the storage decision. You code; this doc is the contract.

## Scope

In:
- order types: **Limit**, **Market** (IOC/FOK optional, later);
- lifecycle: accept → (rest | match) → partial fill → filled; **cancel**; **replace**
  (cancel + re-add, new time priority);
- matching: **price-time priority** — best price first, FIFO within a price; partial fills;
- trade output: `Trade{price, qty, maker_id, taker_id}` to a sink.

Out (explicitly): network/wire protocol, multi-symbol, persistence, risk/position checks,
self-trade prevention. Those come later or never.

## Model (fields)

```
Order  { id:u64, side:'B'|'S', slot:u32, qty:u32, prev:u32, next:u32 }   // intrusive queue
Level  { total:u32, count:u32, head:u32, tail:u32 }                     // + FIFO head/tail
Book   { hot_:Level[], occ_:Occupancy, cold_:map, registry:id->Order }
Trade  { price:i64, qty:u32, maker:u64, taker:u64 }
```

## Tasks (each with a Done)

- T0 scaffold — engine target (CMake), gtest wired, stub `Engine` with the public API.
  Done: `make build`/`make test` green on the stub.
- T1 order model + registry — `Order`, id allocation, registry add/lookup/remove.
  Done: unit tests for registry add/find/erase.
- T2 resting book — per-level FIFO queue on the ladder (`head`/`tail`, intrusive links);
  `rest(order)` appends, `unlink(order)` O(1). Done: FIFO order preserved across a level's
  inserts/removes.
- T3 match loop — `submit(limit|market)`: walk best-first, consume FIFO, emit trades,
  handle partial fills and the market sweep. Done: crossing limit fills at maker prices;
  market sweeps levels until filled or the book empties.
- T4 cancel / replace — `cancel(id)` unlinks + deregisters (O(1)); `replace(id, new)` =
  cancel + re-add. Done: cancel mid-queue leaves the rest FIFO; replace moves time priority.
- T5 correctness — invariants: no crossed book after a match; `submitted == rested + filled
  + cancelled` (qty); registry ⇄ queue consistency; price-time priority across ties.
  Done: `make test` green with the invariant suite.
- T6 bench + docs — micro `submit`/`cancel`/`match` ns/op; a small end-to-end scenario
  (synthetic order flow) with `--stats`; one-line method note. Done: `make bench` table.

## Module layout (mirror P1's seams)

```
engine.h / engine.cpp   matching state only (orders, levels, queues, match loop) — no I/O
(book indexing reused from book.h/bitmap.h: PriceLadder slot math + Occupancy)
main (later)            CLI: feed synthetic orders, print trades/stats — no logic
```

## What to optimize vs ignore

- Optimize: `submit`/`cancel` (registry + queue ops, no allocation on the hot path),
  `match` (walk occupied slots via the bitmap; no scans over empty levels).
- Ignore in v1: concurrency, network, persistence, exotic order types.

## Benchmarks + definition of done

- Micro: `submit` (rest), `cancel`, `match` (partial + full), `replace` — ns/op.
- Macro: N synthetic orders through the engine; msgs/s + trades emitted.
- Targets: zero allocation on the match/cancel path (intrusive queues); no O(levels) scans
  (best-first via occupancy); correctness invariants all green.
